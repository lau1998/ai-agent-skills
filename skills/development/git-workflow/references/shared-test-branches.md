# 共享测试分支集成

本项目的 `dev`、`test`、`pre` 等分支是共享测试分支。以仓库 `AGENTS.md` 的最新规定为准。

1. 除非用户在当前任务中明确指定目标分支和操作范围，不直接在共享测试分支上修改、提交、cherry-pick、改写历史或强制推送。用户明确要求直接修改时，执行前说明分支、文件或操作范围，并只做已授权内容。
2. 功能开发、缺陷修复和测试先在功能分支完成、验证、提交并推送。需要测试环境时，从功能分支向指定测试分支执行合并，推送该合并提交。
3. 合并前获取目标测试分支的最新状态，确认源分支和目标分支。测试分支只承载本次合并及其冲突解决，不夹带功能分支之外的业务修改。
4. 发生冲突时逐文件核对共同基点、功能分支和测试分支。合并结果须保留功能分支的全部需求与改动，并兼顾目标分支已有行为；不得直接接受任一侧的整文件内容来跳过判断。
5. 完成合并后检查冲突标记及完整差异，运行相关定向测试和静态检查，确认无回归或新增问题后再推送。若业务语义无法从代码和需求判断，保留现场并说明待决冲突。
